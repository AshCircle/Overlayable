# Overlayable

[geojson.io](https://geojson.io) 지도 위에 도면 이미지를 띄우고, HongGwart와 층별 노드·간선·사진을 공유하는 Manifest V3 크롬 확장 프로그램입니다.
지도를 드래그/확대축소/회전하면 **사진이 지도에 고정된 것처럼 함께 움직이고**, 필요할 때는 사진을
직접 조작(이동/크기/회전/투명도)해 지도 위 원하는 위치에 다시 고정할 수 있습니다.
빌드 도구·의존성 없이 Vanilla JS로 작성되었습니다.

상세 작업 절차와 주의사항은 [한국어 사용 가이드](docs/USER_GUIDE.md)를 참고하세요.

## 설치 (압축해제된 확장 로드)

1. Chrome 주소창에 `chrome://extensions` 입력
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램 로드** 클릭 → 이 프로젝트 폴더(`Overlayable/`) 선택
4. <https://geojson.io> 접속 — 이 확장은 geojson.io 에서만 동작합니다

## HongGwart 연결과 층별 작업

**백엔드 연결 → 레이어 선택 → 사진 배치 → 점·선 편집 → 저장 상태 확인** 순서로 작업합니다.

1. Chrome 툴바의 Overlayable 아이콘으로 패널을 열고 백엔드 주소와 관리자 API 키를 입력합니다.
2. **연결**을 누릅니다. 새 외부 호스트라면 열린 권한 화면에서 접근을 허용하고 Chrome 요청을 승인한 뒤, geojson.io로 돌아와 **연결**을 다시 누릅니다.
3. `연결됨 · 레이어를 선택하세요`가 표시되면 레이어를 선택하거나 생성합니다.
4. 해당 층의 사진을 업로드하고 geojson.io에서 Point·LineString을 편집합니다. 마지막 변경의 저장 완료를 확인한 뒤 탭을 닫으세요.

`http://example.com:8080`처럼 포트를 포함한 주소도 지원합니다. 호스트 권한은 해당 호스트의 모든 포트에 적용되지만 실제 요청은 입력한 포트로 전송됩니다. HTTP는 키와 데이터를 암호화하지 않으므로 원격 서버에는 HTTPS를 권장합니다.

로컬 기본 주소는 `http://localhost:8080`입니다. 백엔드 `local` 프로필의 기본 키는 `dev-only-change-me`이며, `HONGGWART_ADMIN_API_KEY`로 변경할 수 있습니다. `dev`·`prod` 프로필에서는 키를 별도로 설정해야 합니다. 키는 `chrome.storage.session`에 보관하고 서비스 워커에서 요청하므로 페이지 JavaScript에 주입하지 않습니다. Chrome 재시작이나 확장 리로드 후에는 키 재입력이 필요할 수 있습니다.

### 레이어와 동기화

- 도면 레이어는 여러 실제 건물·층 소속을 지원합니다. **새 노드 소속**을 선택하고 Point별 실제 소속을 저장합니다. G4 도면에서 H1도 함께 편집할 수 있습니다.
- 공용 경로는 지상 보행로·상부 연결통로처럼 **높이·통로별 별도 레이어**로 만듭니다. 공용 중간 노드는 건물 소속이 없고, 실내 여부는 간선별로 지정합니다.
- 여러 도면과 다른 경로를 읽기 전용 참조로 표시할 수 있습니다. 참조 출입구를 선의 끝점에 명시적으로 연결하며 원본 Point를 복제하지 않습니다.
- 레이어 선택 시 현재 GeoJSON과 사진 목록이 해당 레이어의 데이터로 교체됩니다. 연결 전에 편집한 GeoJSON은 자동으로 가져오지 않으므로 먼저 내보내세요.
- 약 **10초마다** 변경을 저장하거나 서버의 최신 데이터를 가져옵니다. Point와 LineString의 끝점·중간 꼭짓점 이동 모두 동기화하며, 같은 노드를 공유하는 점과 선의 좌표도 맞춰집니다.
- 레이어 전환 전에는 현재 변경을 저장합니다. 오류나 버전 충돌로 저장하지 못하면 전환을 중단합니다. 공동 편집은 자동 병합하지 않으므로 가급적 한 층은 한 명이 편집하세요.
- 전환 중에는 선택한 층과 진행 상태를 표시하며, 여러 층을 연속 선택하면 마지막 선택을 반영합니다. 도면을 준비하는 동안 기존 층을 유지하고, 같은 도면은 페이지가 열린 동안 캐시에서 재사용합니다.
- 서버 요청은 각각 최대 20초까지 기다립니다. 시간 초과 시 전환 오류를 확인하고 다시 선택하세요. **저장 요청**의 시간 초과는 서버에서 저장됐을 가능성이 있으므로 로컬 GeoJSON을 내보낸 뒤 원격 상태를 확인하세요.
- **복사**는 단일 소속 레이어에서만 제공하며 새 ID를 가진 노드·내부 간선을 생성합니다. 사진과 외부 연결은 복사하지 않습니다. **이름 변경**만으로 실제 층 매핑이 바뀌지는 않습니다.
- **레이어 삭제**는 이름 재입력이 필요합니다. 외부 연결이 참조하는 노드가 있으면 삭제를 차단하며, 연결을 먼저 해제해야 소유 노드·간선·사진을 삭제할 수 있습니다. 건물 자체를 나타내는 노드는 남습니다.

### 사진 보관과 백업

레이어를 선택하고 올린 사진은 서버에 저장되며 그 레이어에서만 표시됩니다. 레이어를 선택하지 않으면 Chrome 로컬에만 저장되고 팀원에게 공유되지 않습니다.

로컬 사진이 있는 상태에서 레이어를 선택하면 가져올지 묻습니다. 승인하면 사진 파일만 업로드하고 기존 배치는 이전하지 않습니다. **취소해도 레이어 전환은 진행되며 로컬 사진 목록이 교체됩니다.** 전환 전에 사진 영역 하단 **내보내기**로 백업하세요.

상단 **GeoJSON 내보내기**는 점·선, 하단 **내보내기**는 사진·배치 상태를 저장합니다. 하단 **가져오기**는 로컬 사진 목록 병합이며 서버 업로드가 아닙니다. **원격 다시 불러오기**는 미저장 점·선·사진 편집을 서버 상태로 교체하므로 먼저 백업하세요.

### 평면도 기준점 1·2

프론트 애플리케이션의 평면도 배치 기준으로 사용할 두 꼭짓점을 레이어별로 저장합니다. 기준점 API가 추가된 백엔드를 먼저 배포한 뒤 확장을 다시 로드하세요.

1. 도면 레이어를 선택하고 사진 배치(이동·크기·회전)를 마칩니다.
2. 사진 목록에서 서버에 저장된 사진을 선택하고 **평면도 기준점 1·2 → 선택한 사진의 기준점 지정**을 누릅니다.
3. **지도에서 1 찍기**, **지도에서 2 찍기**를 각각 눌러 도면의 두 꼭짓점을 클릭합니다. 빨간 **1**, 파란 **2** 마커가 표시됩니다. `Esc`로 찍기를 취소할 수 있습니다. 지도 기울임(pitch)은 0이어야 합니다.
4. 필요하면 경도·위도 입력란에서 수정하고 **기준점 저장**을 누릅니다. 완성된 두 점은 기존 10초 동기화 및 층 전환 시에도 저장합니다. 두 점이 미완성이거나 저장 오류가 있으면 층 전환을 중단합니다.

C동·A동·L/J 합본 등 같은 종류의 도면에서는 최대한 같은 **물리적 꼭짓점과 1·2 순서**를 사용하세요. 층마다 같은 숫자 좌표를 강제로 복사하지 않습니다. L/J 합본은 하나의 도면 레이어로 두 점을 지정합니다. 공용 경로 레이어에는 기준점을 등록하지 않습니다.

기준점은 그래프 Point·LineString과 별도 데이터이며 GeoJSON 내보내기에 포함되지 않습니다. 좌표는 EPSG:4326의 `longitude`, `latitude` 순서로 저장합니다. 사진 목록의 선택을 바꿔도 저장된 기준점의 사진 연결은 바뀌지 않으며, **선택한 사진의 기준점 지정**으로 사진을 바꾸면 두 점을 새로 지정해야 합니다. 사진을 이동·확대·회전한 후에는 다시 찍으세요.

**기준점 편집 취소**는 마지막으로 읽거나 저장한 기준점으로 되돌립니다. 저장 충돌·실패 시 입력 좌표가 유지되므로 필요하면 좌표를 별도로 복사한 뒤 **원격 다시 불러오기**를 사용하세요. 원격 다시 불러오기는 기준점 초안도 버립니다. 기준점 초안은 탭을 새로고침하거나 닫으면 사라지므로 저장 완료를 확인하세요. 기준점 사진을 서버에서 삭제하면 해당 기준점도 초기화됩니다.

확장은 `GET /api/layers/{layerId}/floor-plan-corners`로 조회하고 관리자 인증을 사용하는 `POST /api/admin/layers/{layerId}/floor-plan-corners`로 `{expectedRevision, imageId, points: [{longitude, latitude}, {longitude, latitude}]}`를 저장합니다. 그래프·사진과 동일한 레이어 revision을 사용하며, 조회만으로 편집 revision을 앞당기지 않습니다.

### 점·간선 연결과 삭제

- 공유 레이어는 **Point와 LineString만** 지원합니다. 선이 화면에서 교차하는 것만으로는 연결되지 않습니다.
- 아직 노드 ID가 없는 선 꼭짓점은 저장 시 같은 레이어·같은 실제 건물·층의 **1m 이내 가장 가까운 노드 ID를 재사용**할 수 있습니다. 가까운 Point들을 일괄 삭제·병합하는 기능은 아닙니다. 연결할 Point를 먼저 저장하고 꼭짓점을 그 위치에 맞추세요.
- 동일 노드의 좌표를 확정할 때 약 2cm 허용 오차를 사용합니다. Point와 선에서 같은 노드를 서로 다른 위치로 이동하면 저장이 거절될 수 있습니다.
- Point 삭제 전에는 연결된 모든 선에서 해당 꼭짓점을 제거하거나 선을 삭제하고 저장하세요. 다른 층과의 연결도 먼저 제거해야 합니다. 연결을 소유한 레이어에서 선을 삭제합니다. 레이어 없는 기존 연결은 이전 도구로 가져와 관리합니다.
- LineString 전체를 삭제하면 구성 간선은 삭제되지만 Point들은 남습니다. `A–B–C`에서 `B` 꼭짓점만 제거하면 `A–C`로 이어집니다. 특정 구간을 끊으려면 남길 경로를 별도 LineString으로 만드세요.

삭제도 자동 동기화 대상입니다. 저장 완료 또는 오류 메시지를 반드시 확인하세요.

### 기존 데이터 이전

소속 변경은 현재 도면 안에서 실제 건물·층을 바꿉니다. 이전 도구는 선택한 노드·간선을 공용 레이어로 옮깁니다. 레이어 없는 데이터도 명시적으로 선택해 가져올 수 있습니다. 미리보기와 별도 실행을 거치며, 원본 노드·간선 ID와 별칭·시설 연결을 유지합니다. 데이터가 바뀌면 미리보기를 다시 해야 합니다.

백엔드 v2를 먼저 배포하고 확장을 다시 로드하세요. 운영 데이터는 자동 재분류하지 않습니다. 확장 테스트는 `node --test tests/*.test.cjs`로 실행합니다.

## 사용법

- **패널 열기/닫기**: 툴바의 Overlayable 아이콘 클릭 (기본은 숨김 상태)
- **이미지 올리기**: 패널의 드롭존을 클릭해 선택하거나 이미지를 끌어다 놓기 — 현재 화면 중앙의 지도 좌표에 고정됩니다
- **지도 연동**: 지도를 드래그/휠 줌/우클릭 회전하면 사진이 지도에 고정된 채 함께 이동/확대/회전됩니다 (패널에 `지도 연동됨` 표시)
- **투명도 / 확대축소 / 회전**: 패널 슬라이더와 `+`/`−`, `±90°` 버튼으로 조절
- **이미지 직접 조작**: 조작 키(macOS는 `⌘ Command`, Windows·Linux는 `Ctrl`)를 **누르고 있는 동안** 이미지 조작 모드 (이미지 둘레에 PowerPoint식 조작 핸들 표시)
  - 본체 드래그 → 이동
  - **꼭짓점 4개 · 모서리 4개 핸들** 드래그 → 비율 유지 크기 조절(반대편 고정)
  - **상단 회전 핸들** 드래그 → 회전 (스냅 없이 정밀, 0.1° 단위 반영)
  - 휠 → 커서 위치 기준 확대/축소, `Shift` + 휠 → 미세 회전
  - 조작한 사진은 **새 위치/크기/각도로 지도에 다시 고정**됩니다
- **웹(지도) 조작 모드**: 조작 키(`⌘`/`Ctrl`)를 떼면 핸들이 사라지고, 사진 위에서도 클릭/스크롤이 지도로 통과
- **리셋**: 변형값 초기화 후 현재 화면 중앙에 다시 고정 · **제거**: 오버레이 제거
- **접기 버튼(▾)**: 패널 본문 접기/펼치기

## 동작 원리

콘텐츠 스크립트는 격리된 월드(ISOLATED world)에서 실행되어 페이지의 지도 객체에 직접 접근할 수
없습니다. 그래서 MAIN world 에 주입되는 `src/bridge.js` 가 geojson.io 의 Mapbox GL 지도
인스턴스를 찾아(공식 노출 전역 `window.api.map` → React 내부 탐색 폴백) `map.on('move')` 마다
카메라 상태(중심 경위도/줌/베어링과 중심의 화면 px)를 `postMessage` 로 중계합니다.
`src/content.js` 는 사진마다 지리 앵커(사진 중심의 경위도 + 앵커 시점 줌/베어링/변형)를 저장해
두고, 카메라가 움직일 때마다 구면 메르카토르 수식(`src/geo.js`)으로 화면 좌표·크기·회전을 다시
유도합니다. 관성 글라이드와 이징 애니메이션도 지도 프레임 단위로 그대로 따라갑니다.

## 알려진 제약

- 지도 **pitch(기울임)** 는 근사 처리됩니다: 사진에 원근 왜곡은 적용되지 않으며, pitch 를 0 으로 되돌리면 정확히 재정렬됩니다.
- 지도 줌으로 사진 scale 이 슬라이더 범위(10~500%)를 벗어나면 슬라이더 썸은 끝에 고정되고 수치 텍스트만 실제 값을 표시합니다. 이 상태에서 휠/핸들 조작은 스냅 없이 이어서 동작합니다.
- 극단적으로 확대해 사진 한 변이 약 200만 px 를 넘으면 렌더 보호를 위해 잠시 숨겨지고, 줌을 되돌리면 다시 나타납니다.
- 지도를 찾지 못하면(사이트 개편 등) 콘솔 경고 1회 후 사진은 예전처럼 **화면 고정**으로 동작하고, 패널에 `지도 감지 대기 중` 이 표시됩니다.

## 문제 해결

연결 주소가 다른 입력란으로 이동할 때 이전 값으로 돌아오면, 키를 먼저 입력하고 주소를 마지막에 입력한 뒤 바로 **연결**을 누르세요. 연결 후 주소·포트를 확인하세요.

**"지도 감지 대기 중"이 사라지지 않을 때** — 미저장 내용을 백업한 뒤 확장과 페이지를 다시 로드해 확인합니다.

1. `chrome://extensions` 에서 Overlayable 카드의 **↻(새로고침)** 버튼을 누르세요. 확장 업데이트는 **geojson.io 탭 새로고침만으로는 반영되지 않을 수 있습니다.** 버전 번호가 같더라도 코드 변경 후에는 확장을 다시 로드하세요.
2. geojson.io 탭을 새로고침한 뒤 개발자 도구(F12) 콘솔에서 `[Overlayable]` 로그를 확인하세요:
   - `브리지 로드됨 — geojson.io 지도 탐색 시작` — 브리지 주입 성공. **이 로그가 아예 없으면 1번(확장 리로드)이 누락된 것입니다.**
   - `지도 연동 성공 (경로: …)` — 정상 동작. 패널에도 `지도 연동됨` 이 표시됩니다.
   - `지도를 찾지 못했습니다 …` (10초 후 경고 1회) — 사이트 구조 변화로 지도 탐색이 실패한 상태입니다. 이슈로 제보해 주세요.

## 개발 확인

Node.js가 설치된 환경에서 회귀 테스트를 실행합니다. 확장 실행 자체에는 Node.js나 빌드 과정이 필요하지 않습니다.

```sh
node --test tests/*.test.cjs
git diff --check
```
