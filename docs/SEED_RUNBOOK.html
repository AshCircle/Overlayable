도면 155장을
노드와 간선으로

HongGwart/Floor Plan/의 이미지 파일을 작업 단위로 확인합니다. 한 도면에 여러 실제 건물·층이 포함될 수 있고, 공용 경로는 높이·통로별 레이어로 관리합니다. 20개 도면 코드·155장을 나눠 맡아, geojson.io에서 점과 선을 찍고 공용 HongGwart 서버에 저장합니다. 이 페이지는 확인된 구간을 입력하고 저장값까지 검수하는 절차를 담고 있습니다. 파일 수는 실제 층 수나 새로 만들 레이어 수가 아닙니다.

기능 전반은 최신 사용자 가이드와 그래프 편집 지침에 있습니다. 이 런북은 그중 시드 입력에 필요한 것만, 실제로 누를 순서대로 추렸습니다.

지키지 않으면 팀 전체 데이터가 틀어지는 세 가지

1

건물 코드와 실제 소속을 확인

C_3.png의 건물 코드는 C입니다. 같은 코드를 쓴 층끼리 한 건물로 묶입니다. 코드는 팀 표기를 따르고 기존 건물·층에 연결됐는지 소속 목록에서 확인합니다. 파일명만으로 혼합 도면 속 모든 노드의 실제 소속을 정하지 않습니다.

2

건물 이름은 팀이 합의한 표대로

한 건물의 이름은 그 건물의 첫 층을 만든 사람이 넣은 값으로 굳습니다. 나중에 다른 층에서 다른 이름을 넣어도 바뀌지 않습니다. 이 이름은 검색 결과에 그대로 나오므로, 작업을 시작하기 전에 20개 도면 코드 이름을 팀에서 확정하고 아래 매핑 칸에 붙여넣으세요.

3

호실 번호는 원문과 팀 표기대로

301, C301, B208-2처럼 실제 표기와 부수 호수를 보존합니다. 팀 규칙에 맞게 입력한 뒤 검색 표시명을 확인하세요. 호실 번호로 실제 건물·층을 추측하지 않습니다.

01

서버에 연결

Chrome을 새로 켤 때마다 다시 합니다.

  1. geojson.io를 엽니다.
  2. Chrome 툴바의 Overlayable 아이콘을 눌러 패널을 엽니다. (기본은 숨김 상태입니다.)
  3. 패널의 HongGwart 공유 레이어 영역에 공용 주소와 Admin API key를 넣습니다.
  4. 연결을 누릅니다.
  5. 새 외부 호스트라면 열린 권한 탭에서 서버 주소 확인 → 접근 허용 → Chrome 요청 승인을 진행합니다. geojson.io로 돌아와 연결을 다시 누릅니다.
  6. 상태 줄이 연결됨 · 레이어를 선택하세요가 되면 끝입니다.
처음 연결하는 외부 호스트는 별도 권한 탭을 거칩니다. localhost와 127.0.0.1은 미리 허용됩니다. 한 번 승인한 호스트 권한은 유지됩니다. 거부했다면 권한 탭의 접근 허용부터 다시 진행하세요.

관리자 편집 API를 제공하는 local/dev 서버를 사용합니다. prod 프로필은 관리자 키가 있어도 관리 API를 404로 차단합니다.

키는 세션에만 남습니다. 백엔드 주소는 저장되지만 관리자 키는 Chrome을 완전히 종료하거나 확장을 다시 로드하면 사라집니다. 다시 연결을 눌러 키만 새로 넣으면 됩니다.

층 정렬 순서는 팀에서 확인한 정수 순서입니다. 아래 변환기는 숫자·B·L 표기로 예시를 만들 뿐, 실제 높이를 검증하지 않습니다. 중층과 복합 도면은 실제 소속·정렬 순서를 따로 확인하세요.

2.1 레이어 만들기

  1. 패널에서 새 레이어를 누릅니다.
  2. 위 표의 값을 순서대로 넣습니다. 도면 종류는 FLOOR_PLAN을 선택합니다.
  3. 목록에 C동 3층 (C 3) 형태로 나타나고, 자동으로 선택됩니다.
중간에 취소하거나 빈 값을 넣으면 아무 안내 없이 조용히 중단됩니다. 입력을 끝낸 뒤 목록에서 생성 여부를 확인하세요. 공용 경로는 SHARED_PATHS를 선택하며 이름·종류만 입력합니다.

해당 건물과 층의 레이어가 이미 존재합니다.가 나오면 누군가 이미 만든 층입니다. 새로 만들지 말고 목록에서 골라 쓰거나, 담당자에게 확인하세요.

2.2 도면 얹고 맞추기

  1. 작업할 레이어가 선택된 상태인지 먼저 확인합니다. (사진은 선택된 레이어에 올라갑니다.)
  2. 지도를 그 건물 위로 옮기고 크게 확대합니다. 지도 기울기는 0으로 둡니다.
  3. 도면 파일을 패널의 업로드 영역에 끌어다 놓습니다. 현재 지도 중심에 놓입니다.
  4. 투명도를 절반쯤 낮춰 배경 지도와 도면이 함께 보이게 합니다.
  5. ⌘(Windows·Linux는 Ctrl)를 누르고 있는 동안만 사진이 조작됩니다.

기존 도면 정렬은 요청 없이 바꾸지 않습니다. 새 도면을 정렬한 뒤 필요하면 서버 사진의 평면도 기준점 1·2를 지정·저장합니다. 사진을 이동·확대·회전했다면 다시 찍어야 합니다. 기준점은 GeoJSON에 포함되지 않습니다.

도면은 확장 로컬 캐시를 사용하며 직접 업로드한 파일도 다시 받지 않습니다. 서버 주소·이미지 주소·해시가 같은 원본만 재사용합니다. 캐시는 최대 128 MiB·256장, 동시 다운로드는 2장입니다. 지도와 배치는 서버에서 확인합니다.

건물 외곽 모서리와 계단실처럼 지도에서도 알아볼 수 있는 곳을 기준점으로 맞추세요. 리셋은 실행 취소가 아니라 변형을 초기화하고 지도 중심으로 되돌리는 버튼입니다.

2.3 노드 찍기

복도 중심선·코너·분기 골격을 먼저 정하고 실제 문 위치의 POI는 짧은 접근 간선으로 연결합니다. 복합 도면은 허용 소속과 새 노드 기본 소속을 먼저 확인하세요. 미확정 문·소속·통행은 추측하지 말고 보류 이유와 필요한 근거를 남깁니다.

geojson.io 위쪽의 Point 도구로 찍습니다. 점 하나를 선택하면 패널의 선택 Point 영역이 열립니다. 값을 넣은 뒤 선택 Point 반영을 반드시 누르세요.

이 지점은노드 유형검색 가능이름 / 호실 번호
강의실·사무실·화장실 등 목적지POI✓이름 필수 · 호실은 원문·팀 표기 유지
계단·엘리베이터 앞VERTICAL_LINK—이름 권장 (3단계에서 찾아야 합니다)

검색 가능은 사람이 목적지로 검색할 지점에만 켭니다. 복도용 WAYPOINT·JUNCTION까지 켜면 검색창이 복도로 뒤덮입니다. 켠 채 이름을 비우면 저장이 거절됩니다 — 검색 가능 Point에는 이름이 필요합니다.

패널의 Node #…는 저장이 끝난 뒤 서버가 준 노드 번호입니다. 아직 저장 후 Node ID가 부여됩니다라면 그 점은 서버에 없습니다.

2.4 간선 그리기

Line 도구로 실제로 걸어갈 수 있는 경로를 긋습니다. 선의 꼭짓점이 노드가 되고, 꼭짓점 사이 구간이 간선이 됩니다.

화면에서 교차해 보이는 것과 이어진 것은 다릅니다. 갈림길에서는 두 선이 같은 꼭짓점을 공유해야 경로가 이어집니다. 저장한 ID·끝점 참조와 4단계의 경로 조회를 함께 확인하세요.
  • 저장할 수 있는 도형은 Point와 LineString뿐입니다. Polygon·Rectangle·Circle 도구는 쓰지 않습니다.
  • 저장 뒤 선의 꼭짓점 자리에 Point가 새로 보이는 것은 정상입니다. 서버가 정리해 돌려준 결과입니다.
  • 한 번 저장되기 전에 같은 노드를 Point에서 한 번, 선에서 또 한 번 서로 다른 위치로 옮기면 저장이 거절됩니다. 한쪽을 옮기고 저장이 끝난 뒤 다음 작업을 하세요.
  • Point를 지우려면 그 점을 지나는 선에서 먼저 꼭짓점을 빼야 합니다. 선이 참조하는 점만 지우면 저장이 거절됩니다.

2.5 저장 확인

열려 있는 동안 약 10초마다 자동으로 동기화합니다. 버튼을 눌러 저장하는 방식이 아닙니다. 상태 줄을 보고 판단하세요.

변경이 없을 때는 현재·연결 레이어의 버전을 확인하며 이전 백엔드에는 기존 전체 조회를 사용합니다. 숨겨진 탭은 원격 조회를 쉬지만 미저장 변경은 계속 저장합니다. 조회 실패 시 간격은 10 → 20 → 40 → 80초 → 최대 2분으로 늘어납니다.

저장 결과 확인이 필요해 자동 저장을 멈췄습니다… 또는 충돌 상태에서는 자동 재전송과 층 전환을 멈춥니다. GeoJSON·사진 배치·미저장 기준점 좌표를 백업한 뒤 원격 다시 불러오기로 서버 상태를 확인합니다. 요청 대기 제한은 20초이며, 시간 초과를 미저장 확정으로 해석하지 않습니다.

검수·재조회까지 여덟 항목을 확인하고 보류가 없을 때만 완료 표시합니다. 다음 층으로 넘어가면 체크가 초기화되고 인벤토리에 표시됩니다.

03

층과 층 잇기

참조 노드를 명시적으로 연결하고 이동 유형·실내 여부·비용을 확인합니다.

요청 범위와 실제 이동 가능성이 확인된 구간만 연결합니다. 원본 Point를 복제하지 않습니다.

  1. 연결 간선을 소유할 레이어를 선택합니다. 다른 레이어의 노드는 해당 도면·공용 경로를 참조로 추가합니다.
  2. 현재 레이어에 LineString을 만들고 선택합니다.
  3. 노드 목록에서 실제 건물·층·이름 또는 ID로 끝점을 찾아 선택한 선의 시작점·끝점에 연결합니다.
  4. 이동 유형, 실내 여부, 양방향 여부를 확인합니다. 계단·엘리베이터의 수동 비용은 구간 수에 맞춰 입력합니다.
  5. 저장 후 연결된 원본 노드 ID, 좌표와 수동 비용을 다시 확인합니다.
참조 끝점은 원본 위치에 고정됩니다. 참조를 숨겨도 연결은 남습니다. 같은 도면 안의 다른 건물·층도 실제 소속으로 구분합니다. 기존 층 연결 버튼은 호환 기능이며 신규 작업은 이 v2 절차를 사용하세요.

관리자 API 클라이언트에서 이 주소를 열고 X-Honggwart-Admin-Key 헤더에 발급받은 키를 설정합니다. 키를 이 문서에 입력하거나 저장하지 않습니다. 내 레이어와 소속을 확인하세요.
검색·노드·경로 세 가지는 키 없이 됩니다. 주소창에 그대로 붙여넣어도 됩니다. 브라우저의 교차 출처 제한을 피하려면 주소창이나 API 클라이언트에서 확인하세요. 예시 노드 ID는 실제 저장된 ID로 바꿉니다.
05

오류 문구 찾기

화면에 뜬 문구를 그대로 붙여넣어 찾으세요.

문구원인과 대처
백엔드 호스트 접근 권한이 필요합니다.열린 권한 탭에서 접근 허용과 Chrome 승인을 마친 뒤 geojson.io에서 연결을 다시 누릅니다.
HTTP(S) 백엔드 URL이 필요합니다.주소에 http:// 또는 https://가 빠졌습니다.
층 정렬 순서는 정수여야 합니다.3층·B1이 아니라 3·-1처럼 정수만 넣습니다. 변환기가 계산해 줍니다.
이미 사용 중인 레이어 이름입니다레이어 이름은 서버 전체에서 하나뿐이어야 합니다. 변환기가 준 이름을 그대로 쓰면 겹치지 않습니다.
해당 건물과 층의 레이어가 이미 존재합니다.그 층은 이미 누군가 만들었습니다. 새로 만들지 말고 목록에서 고르세요.
검색 가능 Point에는 이름이 필요합니다.검색 가능을 켠 점의 이름이 비었습니다. 이름을 넣거나 체크를 끄세요.
좌표는 [lng, lat] 숫자 배열이어야 합니다.JSON을 직접 고치다 좌표 형식이 깨졌습니다. 순서는 경도, 위도입니다.
올바르지 않은 nodeType입니다.유형 값은 WAYPOINT JUNCTION ENTRANCE VERTICAL_LINK POI 다섯 가지뿐입니다.
올바르지 않은 edgeType입니다.간선 종류 값은 CORRIDOR OUTDOOR_PATH STAIR ELEVATOR DOOR입니다. 비워 두면 CORRIDOR가 됩니다.
서로 다른 두 레이어의 노드를 선택해야 합니다.구형 연결 기능의 시작과 끝이 같은 레이어입니다. 신규 연결에는 3단계의 v2 참조 연결을 사용하세요.
같은 건물의 층만 연결할 수 있습니다.구형 연결 기능의 제약입니다. 실제 소속을 확인하고 3단계의 v2 참조 연결 절차를 사용합니다.
다른 레이어 연결에서 사용하는 Point는 먼저 연결을 삭제해야 합니다층 연결에 물려 있는 점을 지우려 했습니다. 연결을 먼저 정리해야 합니다.
이미지는 1 byte 이상 10 MB 이하여야 합니다.도면 파일이 비었거나 10 MB를 넘습니다. 줄여서 올리세요.
이미지 파일만 업로드할 수 있습니다.이미지가 아닌 파일을 올렸습니다.
삭제 확인 이름이 일치하지 않습니다.삭제 확인 창에 레이어 이름을 정확히 다시 입력해야 합니다.
geojson.io 응답 시간이 초과되었습니다.편집기를 찾지 못했습니다. 미저장 내용을 백업하고 chrome://extensions에서 확장을 새로고침한 뒤 geojson.io도 새로고침하세요.
Point 하나를 선택하세요.선이나 여러 개가 선택돼 있습니다. Point 하나만 고르세요.
먼저 저장된 Point 하나를 선택하세요.층 연결은 Node #…가 붙은 점끼리만 됩니다. 저장을 먼저 끝내세요.
충돌: 다른 작업자가 변경했습니다편집을 멈추고 GeoJSON 내보내기로 백업 → 담당자와 조정 → 원격 다시 불러오기. 이 버튼은 저장 안 된 로컬 편집을 버립니다.

일치하는 문구가 없습니다. 동기화 실패: 뒤에 붙은 부분만 넣어 보세요.

하지 말 것

Polygon·Rectangle·Circle로 그리기저장되지 않습니다. Point와 LineString만 씁니다.
JSON에서 id·nodeId·editorId·vertexNodeIds·segmentEdgeIds 고치기노드가 서로 어긋나 저장이 거절되거나 남의 데이터를 덮습니다.
다른 층 JSON을 복사해 ID만 바꿔 붙여넣기단일 소속 도면의 비슷한 층은 복사 버튼을 쓰세요. 노드·간선이 새 ID로 복제됩니다. (도면과 층간 연결은 복사되지 않습니다.)
레이어 삭제외부 연결이 남아 있으면 차단됩니다. 연결을 해제한 뒤 삭제한 소유 점·선·사진은 되돌릴 수 없으므로 담당자와 확인합니다.
같은 층을 두 사람이 동시에 편집자동 병합이 아닙니다. 양쪽에 변경이 있으면 충돌합니다.
내 localhost에 붙어서 작업혼자만의 DB에 쌓입니다. 공용 주소를 씁니다.
관리자 키를 채팅·스크린샷·문서에 남기기서버 전체를 고칠 수 있는 키입니다.
