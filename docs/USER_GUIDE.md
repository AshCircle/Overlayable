# Overlayable × HongGwart 사용 가이드

geojson.io에서 층별 이동 경로를 그리고, 도면 사진과 함께 HongGwart에 저장하는 작업자를 위한 안내서입니다.

편집 프로토콜 v2 기준. 복합 도면과 높이·통로별 공용 경로를 지원합니다. 운영 데이터의 재분류·이전은 자동 실행되지 않습니다.

## 1. 먼저 알아둘 것

- **geojson.io**: 지도 위의 점(Point)과 선(LineString)을 편집합니다.
- **Overlayable**: 작업할 층을 선택하고, 도면 사진을 배치하며, HongGwart와 동기화합니다.
- **HongGwart**: 편집 레이어, 노드의 실제 건물·층, 간선의 실내·실외 속성을 각각 보관합니다.
- **도면 레이어**에는 여러 건물·층이 들어갈 수 있습니다. 예를 들어 G4 도면에서 G4와 H1 노드를 함께 편집합니다.
- **공용 경로 레이어**는 지상 보행로, 상부 연결통로처럼 높이·통로별로 만듭니다. 공용 경로가 반드시 실외인 것은 아닙니다.
- 같은 좌표의 다른 레이어는 별개의 그래프입니다. 레이어 사이의 연결은 원본 노드를 명시적으로 선택해야 만들어집니다.

가장 중요한 작업 순서는 **백엔드 연결 → 레이어 선택 → 사진 배치 → 점·선 편집 → 저장 상태 확인**입니다.

> 레이어를 선택하면 geojson.io의 현재 데이터가 그 레이어의 데이터로 교체됩니다. 연결 전에 geojson.io에서 작업한 내용이 있다면 먼저 내보내세요. 처음 선택할 때 기존 GeoJSON이 자동으로 가져와지는 것은 아닙니다.

## 2. 처음 연결하기

### 준비물

- Chrome에 로드된 Overlayable 확장 프로그램
- 실행 중인 HongGwart 백엔드 주소
- 해당 백엔드의 관리자 API 키
- 사용할 층별 도면 이미지

확장을 아직 설치하지 않았다면 `chrome://extensions`에서 개발자 모드를 켜고, **압축해제된 확장 프로그램 로드**로 Overlayable 저장소 폴더를 선택합니다.

### 연결 순서

1. [geojson.io](https://geojson.io)를 엽니다.
2. Chrome 툴바의 Overlayable 아이콘을 눌러 패널을 엽니다.
3. 패널 상단에 백엔드 주소와 `Admin API key`를 입력합니다.
4. **연결**을 누릅니다.
   - 외부 서버를 처음 연결하면 별도 권한 탭이 열립니다. 서버 주소를 확인하고 **접근 허용**을 누른 뒤 Chrome 권한 요청을 승인합니다. geojson.io로 돌아와 **연결**을 다시 누르세요.
   - `http://example.com:8080`처럼 포트가 있는 주소도 사용할 수 있습니다. 호스트 권한은 해당 호스트의 모든 포트에 적용되지만 실제 요청은 입력한 포트로 전송됩니다.
   - 외부 서버에는 HTTPS를 권장합니다. HTTP는 관리자 키와 데이터를 암호화하지 않습니다.
5. `연결됨 · 레이어를 선택하세요`가 표시되면 기존 레이어를 선택하거나 새로 만듭니다.

로컬 개발 환경의 기본 주소는 `http://localhost:8080`입니다. 백엔드의 `local` 프로필에서 키를 따로 설정하지 않았다면 기본값은 `dev-only-change-me`입니다. `dev`·`prod` 프로필은 `HONGGWART_ADMIN_API_KEY` 설정이 필요합니다. 배포 서버에서는 서버 관리자가 설정한 키를 사용하세요.

주소 입력 후 다른 입력란으로 이동할 때 주소가 이전 값으로 돌아가는 경우가 있습니다. 이때는 관리자 키를 먼저 입력하고, 주소를 마지막에 입력한 뒤 바로 **연결**을 누르세요. 연결 후에도 주소와 포트를 확인하세요.

현재 인증 UI는 아이디·비밀번호 로그인 화면이 아니라 **관리자 API 키 입력 방식**입니다. 키는 브라우저 세션에 보관되므로 Chrome을 재시작하거나 확장을 다시 로드한 뒤에는 재입력이 필요할 수 있습니다. 문서·채팅·스크린샷에 실제 운영 키를 남기지 마세요.

> 팀원의 PC에서 `localhost`는 팀원의 PC를 뜻합니다. 같은 데이터를 보려면 모두 같은 백엔드와 DB를 사용해야 합니다. 원격 서버의 호스트 접근 권한과 연결 가능 여부는 별도로 확인해야 합니다.

## 3. 층별 레이어 만들기

**새 레이어**를 누르면 다음 항목을 순서대로 입력합니다.

| 입력 항목 | T동 10층 예시 | 의미 |
| --- | --- | --- |
| 레이어 이름 | `T동 10층` | 목록에 표시할 이름 |
| 건물 코드 | `T` | 백엔드에서 건물을 식별하는 코드 |
| 건물 이름 | `T동` | 건물 표시 이름 |
| 층 코드 | `10` | 백엔드에서 사용하는 층 값 |
| 층 정렬 순서 | `10` | 층의 순서를 나타내는 정수 |

지하·로비층은 다음처럼 입력할 수 있습니다.

| 레이어 이름 | 건물 코드 | 건물 이름 | 층 코드 | 정렬 순서 예시 |
| --- | --- | --- | --- | --- |
| T동 B1층 | `T` | `T동` | `B1` | `-1` |
| R동 L층 | `R` | `R동` | `L` | `0` |
| C동 3층 | `C` | `C동` | `3` | `3` |

레이어 이름에는 `T동 10층` 같은 고정 형식이 강제되지 않으며, 이름에서 층을 자동 추출하는 방식도 아닙니다. **DB 대응은 별도로 입력한 건물 코드와 층 코드 기준**입니다. 이름은 알아보기 쉽게 지정하고, 코드는 팀에서 합의한 표기를 그대로 사용하세요. 층 코드는 `10층` 대신 `10`, `B1층` 대신 `B1`처럼 통일하는 것이 좋습니다.

**이름 변경**은 표시 이름만 바꿉니다. `C동 3층`을 `C동 4층`으로 이름만 바꿔도 실제 층 매핑은 바뀌지 않습니다. 다른 층을 만들려면 **복사**를 사용하세요.

### 복합 도면의 실제 소속

레이어의 소속 목록에 추가 건물·층을 등록한 다음 **새 노드 기본 소속**을 선택합니다. H1처럼 독립 도면이 없는 층도 등록할 수 있습니다. 점과 선의 새 꼭짓점에는 선택한 소속이 적용됩니다. 기본 소속을 바꿀 때 기존 입력은 이전 소속으로 먼저 저장하고, 새 기본 소속도 서버에 저장합니다.

기존 노드를 재분류할 때는 Point를 선택하고 소속 변경 기능을 사용합니다. 여러 Point를 함께 변경할 수 있습니다. 도면이나 좌표는 이동하지 않습니다. 호실 번호에서 건물·층을 추측하지 말고 실제 도면 표기를 확인하세요.

### 공용 경로 레이어

새 레이어의 유형을 공용 경로로 선택하고 `지상 보행로`, `G–H 상부 연결통로`처럼 구별되는 이름을 지정합니다. 건물·층이나 이미지 업로드 없이 입력할 수 있습니다. 높이가 다른 길은 별도 공용 레이어로 나누고, 계단 등 실제 이동이 가능한 지점만 연결합니다.

공용 중간 노드는 **건물 소속 없음 / 층 없음**입니다. 내부 저장값 `floor: "0"`은 미지정 값이며 실제 0층이나 지상 높이를 뜻하지 않습니다.

## 4. 도면 사진 배치하기

1. 작업할 레이어를 먼저 선택합니다.
2. 지도를 해당 건물 위치로 이동하고 작업하기 편한 크기로 확대합니다.
3. 패널의 이미지 업로드 영역을 클릭하거나, 그 영역에 이미지 파일을 끌어다 놓습니다.
4. 사진 목록에서 조작할 사진을 선택합니다.
5. 사진 위치·크기·각도·투명도를 맞춥니다.

사진은 현재 지도 중심에 배치됩니다. 여러 장을 올릴 수 있으며 선택한 레이어의 사진을 편집합니다. 참조 레이어로 선택한 다른 도면은 원본 정렬 그대로 겹쳐 볼 수 있습니다. 참조 사진은 표시·보기용 투명도만 조절하며, 이동·회전·삭제하거나 현재 레이어의 사진으로 복제하지 않습니다.

### 지도 조작과 사진 조작 구분

| 하고 싶은 일 | 조작 |
| --- | --- |
| 지도 이동·확대, 점과 선 편집 | 조작 키를 누르지 않고 geojson.io 사용 |
| 사진 이동 | macOS `⌘`, Windows/Linux `Ctrl`을 누른 채 사진 본체 드래그 |
| 사진 크기 조절 | 조작 키를 누른 채 꼭짓점·모서리 핸들 드래그 |
| 사진 회전 | 조작 키를 누른 채 상단 회전 핸들 드래그 |
| 사진 확대·축소 | 조작 키를 누른 채 휠 |
| 사진 미세 회전 | 조작 키와 `Shift`를 누른 채 휠 |
| 투명도·크기·각도 수치 조절 | 패널 슬라이더와 버튼 사용 |

조작 키를 놓으면 사진 위에서도 지도와 점·선을 조작할 수 있습니다. 사진을 조정한 뒤에는 지도 이동·확대에 맞춰 함께 움직입니다.

도면을 맞출 때는 건물 외곽이나 계단 위치처럼 비교하기 쉬운 기준점을 사용하세요. 투명도를 낮추면 배경 지도와 도면을 함께 보기 쉽습니다. 정밀 작업에서는 지도 기울기를 0으로 유지하세요. 사진의 원근 왜곡은 지원하지 않습니다.

- **리셋**: 선택 사진의 변형을 초기화하고 현재 지도 중심에 다시 배치합니다. 실행 취소 버튼이 아닙니다.
- **선택 사진 제거 / 사진 목록의 ×**: 공유 레이어에서는 서버 사진 삭제로 이어지므로 다른 작업자에게도 영향을 줍니다.
- 기존 로컬 사진을 레이어로 가져올지 묻는 창은, 현재 선택할 층에 해당하는 사진일 때만 승인하세요.

### 레이어를 선택하지 않고 사진을 올렸다면?

업로드는 가능하지만 사진은 해당 Chrome의 로컬 저장소에만 보관됩니다. 서버에 저장되거나 팀원에게 공유되지는 않습니다.

이 상태에서 레이어를 선택하면 로컬 사진을 가져올지 묻습니다.

- **확인**: 사진 파일을 선택한 레이어에 업로드합니다. 기존 위치·크기·각도 등의 배치는 함께 이전되지 않으므로 다시 맞춰야 합니다.
- **취소**: 사진 가져오기만 취소합니다. 레이어 전환은 진행되며, 현재 사진 목록은 선택한 레이어의 사진으로 교체됩니다.

> 로컬 사진 목록은 별도 보관함으로 남지 않습니다. 레이어 전환 전에 하단 **내보내기**로 사진과 배치를 백업하세요. 처음부터 레이어를 선택하고 사진을 올리는 것이 안전합니다.

## 5. 점과 선으로 이동 경로 만들기

### 기본 편집

1. geojson.io 상단의 **Point** 도구로 출입구·분기점·목적지 등의 위치를 찍습니다.
2. **Line** 도구로 이동 경로를 그립니다. 선은 두 개 이상의 꼭짓점을 가져야 합니다.
3. **Select** 도구로 점이나 선을 선택해 위치를 조정합니다.
4. 동기화 후 생성된 Point와 선의 연결 상태를 확인합니다.

HongGwart에 저장할 수 있는 도형은 **Point와 LineString뿐**입니다. geojson.io에 Polygon·Rectangle·Circle 도구가 보여도 공유 레이어 편집에는 사용하지 마세요.

선의 꼭짓점은 노드에 대응하고, 꼭짓점 사이 구간은 간선이 됩니다. 저장 후 서버가 데이터를 정리하면서 선의 꼭짓점에 해당하는 Point가 추가로 표시될 수 있습니다. 이것은 정상 동작입니다.

화면에서 선 두 개가 교차한다고 반드시 연결된 경로가 되는 것은 아닙니다. 분기점에는 서로 공유하는 꼭짓점·노드가 있는지 확인하세요. 가까운 좌표는 서버의 연결 판정에 영향을 줄 수 있으므로, 서로 다른 경로를 임의로 겹쳐 놓지 않는 것이 좋습니다.

### 점이나 선을 끌어 이동하면?

- **Point를 이동**하면 해당 노드와 연결된 LineString의 꼭짓점도 서버 저장 후 같은 위치로 맞춰집니다.
- **LineString의 끝점이나 중간 꼭짓점을 이동**하면 대응 Point와 같은 노드를 사용하는 다른 선에도 반영됩니다.
- 한 번의 저장 전에 동일 노드를 Point와 선에서 각각 서로 다른 위치로 옮기면 저장이 거절될 수 있습니다. 한 표현을 이동하고 동기화가 끝난 다음 이어서 작업하세요.

### 선의 꼭짓점 근처에 Point가 있으면?

서버는 저장할 때, 아직 노드 ID가 없는 LineString 꼭짓점에 대해 **같은 레이어이며 같은 실제 건물·층 소속인 1m 이내 노드 중 가장 가까운 노드 ID를 재사용**할 수 있습니다. 이미 저장된 노드와 해당 저장 요청에서 먼저 처리된 좌표가 후보입니다. geojson.io 자체에서 Point를 지우는 기능이 아니라, 선과 Point가 같은 DB 노드를 공유하도록 하는 처리입니다.

- 이미 노드 ID가 있는 꼭짓점은 가까운 다른 Point로 자동 재연결되지 않습니다.
- 서로 가까운 독립 Point들을 일괄 병합하거나 삭제하지 않습니다.
- 1m는 연결 후보 탐색 거리이지 좌표 차이를 모두 허용하는 기준은 아닙니다. 동일 노드의 좌표를 확정할 때 약 2cm 허용 오차를 사용하므로, 서로 다른 이동 위치를 보내면 저장이 거절될 수 있습니다.

연결하려는 Point를 먼저 저장하고 그 위치에 선의 꼭짓점을 맞추세요. 저장 후 Point와 선의 위치·연결을 다시 확인하세요.

### 점 또는 간선 삭제하기

geojson.io의 **Select** 도구로 삭제 대상을 선택하고 휴지통 버튼을 사용합니다. 삭제도 다음 자동 동기화 때 DB에 반영되므로 완료 상태를 확인하세요.

**Point를 삭제하려면:**

1. 연결된 선이 없다면 Point를 바로 삭제합니다.
2. 선이 연결되어 있다면 그 Point를 사용하는 모든 LineString을 삭제하거나, 각 선에서 해당 꼭짓점을 제거합니다.
3. 선 변경의 저장 완료를 확인한 다음 Point를 삭제합니다. 선이 계속 참조하는 Point만 삭제하면 저장이 거절됩니다.
4. 계단·엘리베이터 등 다른 레이어와의 연결도 있다면 해당 연결을 먼저 삭제해야 합니다. 연결을 소유한 레이어에서 해당 선을 편집하세요. 구형 API로 만든 레이어 없는 연결은 이전 도구로 편집 레이어에 가져온 뒤 관리할 수 있습니다.

**간선을 삭제하려면:**

- LineString 전체를 삭제하면 그 선을 구성하던 모든 구간 간선이 삭제됩니다. 별도로 표시된 Point들은 남습니다.
- `A–B–C`에서 중간 꼭짓점 `B`만 제거하면 `A–C` 간선이 생깁니다. 경로를 끊는 동작이 아닙니다.
- 특정 구간만 끊으려면 남길 경로를 별도 LineString으로 구성하세요. 예를 들어 `A–B–C–D`에서 `B–C`만 없애려면 기존 선을 지우고 `A–B`, `C–D` 두 선으로 만듭니다. 기존 Point는 유지하고 그 위치에 꼭짓점을 맞춥니다.

삭제 전에 상단 **GeoJSON 내보내기**로 백업하세요. 저장 실패 상태라면 서버에서는 삭제되지 않은 것이므로 오류를 해결한 뒤 다시 확인해야 합니다.

### Point 속성 입력

Point 하나를 선택한 뒤 Overlayable의 **선택 Point** 영역을 사용합니다.

| 항목 | 사용 예시 |
| --- | --- |
| 이름 | `T동 10층 엘리베이터`, `C301 강의실` |
| 노드 유형 | 아래 분류에서 선택 |
| 검색 가능 | 목적지 검색에 사용할 Point라면 체크 |
| 호실 번호 | `C301` 등 팀에서 정한 표기 |

유형은 일반 경유점 `WAYPOINT`, 분기점 `JUNCTION`, 출입구 `ENTRANCE`, 층간 이동 지점 `VERTICAL_LINK`, 관심 지점 `POI` 중 선택합니다. 구체적인 분류 기준은 팀에서 통일하세요.

입력 후 반드시 **선택 Point 반영**을 누릅니다. 검색 가능을 체크한 Point에는 이름이 필요합니다. `Node #…`는 저장 후 부여된 DB 노드 ID입니다.

### JSON을 직접 수정할 때

geojson.io의 JSON 편집기로 수정한 내용도 동기화 대상입니다. 좌표 순서는 `[경도, 위도]`입니다.

기존 데이터의 `id`, `properties.overlayable`, `nodeId`, `editorId`, `vertexNodeIds`, `vertexRefs`, `segmentEdgeIds` 등 식별·연결 정보는 임의로 수정하거나 제거하지 마세요. 새 층을 만들 때 기존 JSON의 ID를 수동으로 바꾸는 대신 레이어 **복사** 기능을 사용하세요.

## 6. 비슷한 층은 복사해서 작업하기

복사는 단일 소속 도면 레이어에만 제공됩니다. 복합·공용·외부 참조 레이어는 다른 층으로 잘못 재분류되지 않도록 복사를 지원하지 않습니다.

예: C동 3층을 바탕으로 C동 4층 만들기

1. `C동 3층` 레이어를 선택합니다.
2. 저장 상태를 확인하고 **복사**를 누릅니다.
3. 레이어 이름 `C동 4층`, 건물 코드 `C`, 건물 이름 `C동`, 층 코드 `4`, 정렬 순서 `4`를 입력합니다.
4. 새 레이어가 선택되면 4층 도면을 업로드합니다.
5. 달라진 방·출입구·경로를 수정합니다. 복사된 이름과 호실 번호도 새 층에 맞게 확인하세요.

복사되는 것은 **노드와 레이어 내부 간선**입니다. 새 노드·간선에는 별도 ID가 부여되므로 새 층을 편집해도 원본은 바뀌지 않습니다.

**도면 사진과 층간 연결은 복사되지 않습니다.** 각 층에 맞는 사진을 따로 올리고 층간 연결도 별도로 설정하세요.

## 7. 기존 노드와 명시적으로 연결하기

1. 연결 간선을 관리할 레이어를 선택합니다.
2. 다른 레이어의 노드라면 해당 도면·공용 경로 레이어를 참조로 추가합니다. 참조 데이터는 편집할 수 없습니다. 현재 레이어의 노드는 바로 연결 후보로 표시됩니다.
3. 현재 레이어에서 LineString을 만들고 선택합니다.
4. 노드 목록에서 건물·층·노드명 또는 ID로 끝점을 찾아 선택합니다. 같은 G4 도면에 있는 H1 노드도 이 방식으로 연결합니다.
5. 선택 선의 시작점 또는 끝점을 해당 노드에 연결합니다. 건물 출입구 Point는 복제하지 않습니다.
6. 선택 선의 이동 유형, 실내 여부, 양방향 여부를 확인합니다. 계단·엘리베이터는 필요한 수동 이동 가중치를 지정합니다.
7. 저장 후 연결된 원본 노드 정보를 확인합니다.

참조 끝점은 원본 노드의 위치에 고정됩니다. 다른 위치로 끌면 저장 오류가 표시됩니다. 실제 이동은 원본 레이어에서 하거나 연결을 해제한 뒤 진행하세요. 참조 사진·점을 숨겨도 이미 만든 연결은 삭제되지 않습니다.

간선의 `edgeType`과 `indoor`는 별개입니다. 야외 계단은 `STAIR + indoor=false`, 실내 공용 통로는 `CORRIDOR + indoor=true`로 지정합니다. 자동 거리 간선은 좌표를 따라 거리를 계산하고, 수동 가중치는 위치 변경·이전에도 유지됩니다. 선 전체의 수동 값은 구간 수에 맞춰 입력합니다.

### 기존 데이터 이전

**소속 변경**은 같은 도면 안의 실제 건물·층만 바꾸고, **이전**은 편집 레이어를 바꿉니다.

1. 이전 대상 공용 레이어를 준비합니다.
2. 현재 레이어의 노드·간선을 선택하거나 레이어 없는 데이터 후보를 조회하여 명시적으로 선택합니다.
3. 이전 미리보기에서 이동 노드·실제 간선 구간·남는 끝점·영향 레이어를 확인합니다. 선택 노드에 연결된 간선도 함께 포함됩니다.
4. 미리보기를 확인한 다음 별도 실행 버튼으로 이전합니다.
5. 대상과 원본에서 연결 및 ID 보존을 확인합니다.

건물 출입구는 선택하지 않고 원소속에 남겨 참조합니다. 레이어 없는 끝점은 참조할 편집 소유자가 없으므로 함께 선택해 가져와야 합니다. 미리보기 이후 데이터가 바뀌면 실행을 거절하며 다시 미리보기를 해야 합니다. 이전은 원본 도면을 변경하지 않으며 노드·간선 ID와 별칭·시설 연결을 유지합니다.

## 8. 자동 저장과 공동 작업

열린 페이지에서 약 **10초마다** 현재 레이어를 동기화합니다. 로컬 변경이 있으면 저장하고 정리된 서버 데이터를 반영하며, 변경이 없으면 서버의 최신 버전을 확인합니다. 사진 업로드·삭제 등은 별도 서버 요청으로 처리됩니다.

| 상태 표시 | 의미와 다음 행동 |
| --- | --- |
| `저장 중…` | 요청 처리 중. 완료 상태를 기다립니다. |
| `저장됨 · revision …` | 변경을 서버에 저장했습니다. |
| `동기화됨 · revision …` | 확인한 서버 버전과 동기화된 상태입니다. |
| `… 전환 중 · …` | 선택한 층으로 이동하기 위해 현재 변경을 저장하거나 도면을 준비하고 있습니다. |
| `원격 변경 반영 · revision …` | 다른 탭·작업자의 변경을 가져왔습니다. |
| `동기화 실패: …` | 저장 성공으로 간주하지 말고 원인을 확인합니다. |
| `충돌: 다른 작업자가 변경했습니다…` | 로컬 내용을 백업한 뒤 최신 버전과 조정합니다. |

`revision`은 레이어의 변경 버전입니다. 지도만 확대·이동한 경우에는 사진의 화면상 크기가 바뀌어도 저장할 편집으로 취급하지 않습니다.

참조한 끝점의 원본 레이어뿐 아니라, 현재 노드에 연결된 다른 레이어의 간선 버전도 검사합니다. 현재 레이어의 revision이 같아도 관련 레이어가 바뀌면 동기화·충돌 대상이 됩니다. 외부 간선이 연결된 원본 도면도 v2 클라이언트를 사용해야 합니다.

레이어 전환 전에는 현재 변경을 먼저 저장합니다. 네트워크 오류나 충돌 때문에 저장하지 못하면 전환이 중단됩니다. 탭을 닫거나 새로고침하기 전에도 마지막 변경의 저장 완료를 확인하세요. 10초는 타이머 간격이며 네트워크 지연이나 브라우저의 백그라운드 제한 때문에 반영이 더 늦어질 수 있습니다.

전환 중에도 층을 다시 선택할 수 있으며 마지막으로 선택한 층을 반영합니다. 이때 사진·레이어 관리 버튼은 잠시 비활성화됩니다. 새 도면을 모두 받은 뒤 지도를 교체하므로 이미지 다운로드가 실패하면 기존 층의 지도와 도면이 유지됩니다. 같은 이미지 내용은 페이지 내 캐시를 재사용합니다.

서버 요청 하나당 대기 제한은 20초입니다. 조회·도면 요청이 시간 초과되면 연결 상태를 확인하고 원하는 층을 다시 선택하세요. 저장 요청이 시간 초과되었다면 서버에서 처리됐을 수도 있으므로, 상단 **GeoJSON 내보내기**로 로컬 편집을 백업한 뒤 원격 상태를 확인하세요.

### 팀 작업 원칙

- 모두 같은 서버 주소와 해당 서버의 관리자 키를 사용합니다.
- 가능하면 **한 층은 한 명이 편집**하도록 나눕니다. 같은 층을 보는 다른 탭에서는 편집하지 않는 것이 안전합니다.
- 공동 작업은 실시간 커서 공유나 자동 병합이 아닙니다. 양쪽에 변경이 있으면 충돌할 수 있습니다.
- 다른 사람이 만든 레이어나 바꾼 이름이 목록에 안 보이면 현재 변경을 먼저 저장·백업한 뒤 페이지를 새로고침합니다. 현재 레이어 내용의 주기적 동기화와 레이어 목록 갱신은 다릅니다.

### 충돌이 발생했을 때

1. 추가 편집을 잠시 멈춥니다.
2. 상단 **GeoJSON 내보내기**로 현재 점·선을 백업합니다.
3. 사진 배치도 보존해야 한다면 하단 **내보내기**로 사진 상태를 별도로 백업합니다.
4. 다른 작업자와 어느 변경을 남길지 정합니다.
5. 백업을 확인한 후 **원격 다시 불러오기**를 누릅니다.
6. 최신 데이터 위에 필요한 변경만 다시 적용하고 저장을 확인합니다.

> **원격 다시 불러오기**는 로컬의 미저장 편집을 버리고 서버의 점·선·사진 상태로 교체합니다. 충돌한 JSON 전체를 그대로 덮어넣으면 다른 작업자의 변경을 없앨 수 있으므로, 자동 병합이나 복구 버튼으로 생각하지 마세요.

## 9. 내보내기와 삭제 주의사항

| 버튼 | 대상 |
| --- | --- |
| 상단 `GeoJSON 내보내기` | 현재 편집기의 점·선 데이터 |
| 사진 영역 하단 `내보내기` | 오버레이 사진과 배치 상태 JSON |
| 사진 영역 하단 `가져오기` | 오버레이 상태 JSON을 로컬 사진 목록에 병합 |

하단 **가져오기**는 GeoJSON 가져오기가 아니며, 가져온 사진이 곧바로 공유 서버에 업로드되는 것도 아닙니다. 공유 사진을 추가하려면 대상 레이어를 선택한 뒤 이미지 업로드 영역을 사용하세요. 두 종류의 내보내기 파일은 백엔드 전체 DB 백업이나 층간 연결까지 포함하는 완전한 복원본이 아닙니다.

레이어 **삭제**는 이름을 정확히 다시 입력해야 실행됩니다. 다른 레이어의 연결이 해당 노드를 참조하면 삭제가 차단됩니다. 연결을 먼저 해제한 뒤 삭제하면 해당 레이어 소유 노드·간선·사진이 삭제되며 다른 작업자에게도 영향을 줍니다. 건물 자체를 나타내는 노드는 남습니다. UI에 휴지통·복원 기능은 없으므로 삭제 전에 팀 확인과 필요한 백업을 완료하세요.

## 10. 문제가 생겼을 때

| 증상 | 확인할 것 |
| --- | --- |
| 패널이 보이지 않음 | Chrome 툴바의 Overlayable 아이콘을 누릅니다. 새로고침 뒤 숨겨져 있을 수 있습니다. |
| 백엔드 연결 실패 | 서버 실행 여부, 주소·포트, 관리자 키를 확인합니다. |
| 재시작 후 인증 실패 | 관리자 키를 다시 입력해 연결합니다. |
| 지도 감지 대기 / 편집기 응답 시간 초과 | 편집을 먼저 백업하고 확장 새로고침 후 geojson.io도 새로고침합니다. 계속 실패하면 사이트 구조 변경 가능성을 개발자에게 알립니다. |
| Point 반영 버튼 비활성 | 선이 아니라 Point 하나를 선택했는지 확인합니다. |
| 검색 가능한 Point 저장 실패 | 이름이 비어 있지 않은지 확인합니다. |
| Point·선 이동 위치가 다르다는 오류 | 같은 노드의 여러 표현을 서로 다른 위치로 옮겼는지 확인합니다. 백업 후 좌표를 일치시킵니다. |
| 삭제한 Point가 저장되지 않음 | 그 Point를 참조하는 선이나 다른 층과의 연결이 남아 있는지 확인합니다. |
| 다른 층의 사진을 함께 보고 싶음 | 해당 레이어를 참조로 추가합니다. 참조 사진은 현재 레이어의 업로드 사진이 아닙니다. |
| 사진이 지도와 어긋남 | 지도 연동 상태와 기울기를 확인합니다. pitch 0에서 다시 맞춥니다. |
| 가져온 사진이 사라지거나 공유되지 않음 | 하단 JSON 가져오기는 로컬 병합입니다. 공유 레이어의 업로드 영역으로 추가하세요. |

확장 업데이트를 반영할 때는 `chrome://extensions`에서 Overlayable 카드의 새로고침을 누른 뒤 geojson.io 탭도 새로고침합니다. 미저장 내용은 먼저 백업하세요.

## 11. 작업 종료 체크리스트

- [ ] 올바른 건물·층 레이어에서 작업했다.
- [ ] 사진과 노드·간선이 도면에 맞는다.
- [ ] 새 층으로 복사한 이름·호실 번호를 확인했다.
- [ ] 분기점과 출입구가 의도한 선에 연결되어 있다.
- [ ] 필요한 층간 연결을 별도로 설정했다.
- [ ] 마지막 편집 이후 저장 완료를 확인했고 오류·충돌 표시가 없다.
- [ ] 중요한 변경은 GeoJSON과 사진 상태를 각각 내보냈다.
- [ ] 다음 작업자에게 작업한 층과 주의할 점을 전달했다.

## 12. v2 업데이트와 경로 안내

백엔드를 먼저 v2로 업데이트한 다음 확장을 다시 로드합니다. 새 확장은 v2를 지원하지 않는 백엔드의 스냅샷을 거절하고 업데이트 필요 메시지를 표시합니다. 구형 확장은 기존 단일 소속 레이어만 사용하며, 복합·공용·외부 참조 레이어의 저장은 서버에서 차단됩니다. 신규 레이어 생성만으로 기존 데이터가 자동 편입되지 않습니다.

경로는 레이어의 이름 대신 실제 노드 소속을 사용합니다. G4→H1 평면 통로는 층 코드가 달라도 내려가는 계단으로 안내하지 않습니다. 실내 공용 통로는 `indoor=true`이면서 건물·층 문맥이 없을 수 있습니다. 공용 계단의 층·방향을 알 수 없으면 “계단을 이용하세요”라고 안내하며 0층으로 안내하지 않습니다.
