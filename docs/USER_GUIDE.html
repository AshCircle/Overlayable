01

설치와 패널

빌드도 설치 프로그램도 없습니다. 폴더를 그대로 Chrome에 올립니다.

  1. Chrome 주소창에 chrome://extensions를 입력합니다.
  2. 우측 상단 개발자 모드를 켭니다.
  3. 압축해제된 확장 프로그램 로드를 누르고 Overlayable/ 폴더를 선택합니다.
  4. geojson.io를 엽니다. 이 확장은 geojson.io에서만 동작하며 다른 사이트에서는 아무것도 하지 않습니다.
  5. Chrome 툴바의 Overlayable 아이콘을 누릅니다. 페이지 우상단에 패널이 나타납니다.
아이콘을 눌러도 팝업 창은 뜨지 않습니다. 아이콘은 페이지 안의 패널을 보이거나 숨기는 스위치입니다. 패널은 기본이 숨김이라, 새로고침한 뒤 안 보이면 아이콘을 한 번 더 누르면 됩니다. 설정 페이지도 따로 없습니다. 모든 조작은 패널에서 합니다.

패널 해부도

위에서 아래 순서입니다. 이 문서에서 이렇게 표시한 것은 패널이나 화면에 실제로 적힌 문구입니다.

  • 헤더제목, 현재 모드 배지(웹 모드 / 이미지 모드), 접기 버튼 ▾
  • HongGwart 공유 레이어서버 주소, Admin API key, 연결, 상태 줄, 레이어 목록, 새 레이어·복사·이름 변경·삭제, 층 연결 버튼, GeoJSON 내보내기, 원격 다시 불러오기, 선택 Point 편집기
  • 업로드 영역이미지를 끌어다 놓거나 클릭해 선택. 여러 장을 한 번에 올릴 수 있습니다.
  • 사진 목록가장 최근에 올린 사진이 맨 위. 클릭하면 선택, ×는 삭제.
  • 투명도 · 확대/축소 · 회전선택한 사진 하나에만 적용되는 슬라이더. 확대는 10~500%, 회전은 0.1° 단위.
  • 리셋 · 선택 사진 제거변형 초기화와 삭제. 04에서 자세히.
  • 내보내기 · 가져오기사진과 배치 상태를 JSON 파일로. 점·선의 내보내기는 위쪽 GeoJSON 내보내기이고 이것과 다릅니다.
  • 지도 연동 상태지도 연동됨 · 사진이 지도에 고정됩니다가 정상. 지도 감지 대기 중이 계속되면 증상별 해결.
확장 코드가 바뀌었다는 안내를 받으면 chrome://extensions의 Overlayable 카드에서 ↻를 누른 다음 geojson.io 탭도 새로고침하세요. geojson.io 탭만 새로고침해서는 새 코드가 실리지 않습니다. 새로고침 전에 아직 저장되지 않은 편집이 있는지 먼저 확인하세요.
02

서버 연결과 권한

Chrome을 새로 켤 때마다 다시 합니다. 처음 연결하는 서버라면 한 단계가 더 있습니다.

준비물

  • 팀이 함께 쓰는 서버 주소. 예: https://map.example.com 또는 http://10.0.0.5:8080
  • 그 서버의 관리자 API 키. 서버 운영자가 정해 나눠 주는 문자열입니다.
  • 작업할 층의 도면 이미지 파일. 10 MB 이하의 이미지 형식.

연결 순서

  1. 패널의 HongGwart 공유 레이어 영역에서 Admin API key 칸에 키를 먼저 넣습니다.
  2. 그다음 서버 주소 칸에 주소를 넣고, 다른 곳을 클릭하지 말고 바로 연결을 누릅니다.
  3. 상태 줄이 연결됨 · 레이어를 선택하세요로 바뀌면 끝입니다. 레이어 목록에 팀원이 만든 층들이 보여야 합니다.

주소를 넣고 다른 칸으로 옮겨 가면 주소가 이전 값으로 되돌아가는 경우가 있습니다. 그래서 키를 먼저, 주소를 마지막에 넣습니다. 연결된 뒤 주소 칸에 포트까지 그대로 남아 있는지 한 번 확인하세요.

권한은 두 겹입니다

"권한이 없다"는 말이 두 가지 다른 상황을 가리킬 수 있습니다. 어느 쪽 문제인지 알면 대처가 바로 정해집니다.

잠금 1 · 호스트 권한

내 Chrome이 그 주소에 접근해도 되는가

Chrome은 확장이 아무 서버에나 접근하는 것을 막습니다. localhost와 127.0.0.1은 미리 허용돼 있고, 그 밖의 주소는 처음 한 번 사용자가 직접 허용해야 합니다. 한 번 허용하면 Chrome을 껐다 켜도 유지됩니다.

잠금 2 · 관리자 키

서버가 내 요청을 받아 주는가

공유 레이어 관리 API는 요청에 붙은 관리자 키를 확인합니다. 로그인 화면이나 개인 계정은 없습니다. 팀 전체가 같은 키 하나를 씁니다. 키는 Chrome을 완전히 종료하거나 확장을 다시 로드하면 지워지므로 그때마다 다시 넣습니다.

처음 연결하는 외부 서버라면

연결을 눌렀는데 상태 줄에 아래 문구가 뜨고 새 탭이 열립니다. 정상입니다. 잠금 1을 여는 절차가 시작된 것입니다.

동기화 실패: 열린 권한 화면에서 접근을 허용한 뒤, geojson.io로 돌아와 연결을 다시 누르세요.

  1. 새로 열린 탭 Overlayable 백엔드 접근 권한에서 표시된 서버 주소가 내가 넣은 주소와 같은지 확인합니다.
  2. 접근 허용을 누릅니다.
  3. Chrome이 띄우는 권한 요청 창에서 허용을 누릅니다.
  4. 탭에 허용되었습니다. geojson.io로 돌아가 연결을 다시 누르세요.가 보이면 이 탭은 닫아도 됩니다.
  5. geojson.io 탭으로 돌아와 연결을 다시 누릅니다. 이번에는 연결됨 · 레이어를 선택하세요가 됩니다.
Chrome 창에서 거부했다면 권한 탭에 권한을 허용하지 않았습니다. 연결하려면 접근 허용을 다시 누르세요.가 뜹니다. 같은 탭에서 접근 허용을 다시 누르면 됩니다. 탭을 닫으면 요청이 취소되고, 다음에 연결을 누르면 처음부터 다시 시작합니다.

주소에 관해

  • http:// 또는 https://로 시작해야 합니다. 빠지면 HTTP(S) 백엔드 URL이 필요합니다.
  • 포트가 있는 주소(http://10.0.0.5:8080)도 됩니다. 허용은 호스트 단위로 받고, 요청은 넣은 포트로 갑니다. 같은 호스트의 다른 포트로 바꿔도 다시 허용받을 필요는 없습니다.
  • 주소에 아이디·비밀번호·?·#가 들어가면 거부됩니다. 백엔드 URL에는 계정 정보, 쿼리 또는 fragment를 넣지 마세요.
  • 외부 서버는 HTTPS를 쓰세요. HTTP는 키와 데이터를 그대로 네트워크에 내보냅니다. 권한 탭에도 같은 경고가 표시됩니다.
  • 팀원 PC의 localhost는 팀원 PC입니다. 각자 localhost에 붙으면 데이터가 각자의 컴퓨터에 따로 쌓입니다. 팀 공용 주소를 쓰세요.

관리자 편집 API를 제공하는 local/dev 서버에 연결합니다. prod 프로필은 관리자 키가 있어도 관리 API를 404로 차단합니다.

키에 관해

  • 키가 틀리면 동기화 실패: 관리자 API 키가 올바르지 않습니다. 키를 다시 넣고 연결을 누릅니다. 로컬 개발 서버라면 별도 설정이 없을 때 기본 키가 dev-only-change-me이지만, 팀 서버의 키는 운영자에게 받아야 합니다.
  • 키 하나로 모든 레이어를 만들고 지울 수 있습니다. 레이어별 개인 권한은 구분하지 않습니다. 서버 데이터를 삭제할 때는 담당자와 확인하고, 원격 다시 불러오기 전에는 내 미저장 편집을 백업하세요.
  • 키는 문서·채팅·스크린샷에 남기지 않습니다. 키는 페이지 JavaScript에 노출되지 않고 확장 안에서만 서버로 보내집니다.
03

층 레이어

도면 소유 레이어와 노드의 실제 건물·층을 구분합니다. 복합 도면과 공용 경로를 지원합니다.

기존 레이어 선택

목록에서 고르는 순간 geojson.io 편집기의 내용과 사진 목록이 그 레이어의 데이터로 통째로 바뀝니다. 연결 전에 geojson.io에서 그려 둔 것이 있다면 GeoJSON 내보내기로 먼저 파일로 받아 두세요. 자동으로 가져와 주지 않습니다.

레이어를 바꾸기 직전에 현재 레이어의 미저장 변경을 먼저 저장합니다. 저장이 실패하면(오류·충돌) 전환도 멈춥니다. 마지막으로 선택한 레이어는 기억해 두었다가 다음에 페이지를 열 때 다시 선택해 줍니다.

새 레이어 만들기

새 레이어를 누르면 먼저 이름과 종류를 묻습니다. FLOOR_PLAN은 건물·층 정보까지 총 여섯 항목, SHARED_PATHS는 이름·종류 두 항목을 입력합니다. 완료 후 목록에서 생성 여부를 확인하세요.

뜨는 질문T동 10층T동 지하 1층R동 로비뜻
1새 레이어 이름T동 10층T동 B1층R동 L층목록에 보이는 이름. 서버 전체에서 하나뿐이어야 합니다(대소문자 구분 없음).
2레이어 종류FLOOR_PLANFLOOR_PLANFLOOR_PLAN도면 또는 공용 경로(SHARED_PATHS).
3건물 코드 (예: T, C)TTR건물을 묶는 기준. 같은 코드끼리 한 건물입니다.
4건물 이름 (예: T동)T동T동R동검색 결과에 나오는 건물 표시 이름.
5층 코드 (예: 10, B1, L)10B1L층을 구분하는 값. 10층이 아니라 10.
6층 정렬 순서 (예: B1=-1, L=0, 10=10)10-10층의 높이 순서. 정수만. 지하는 음수, 로비는 0.

다 넣으면 목록에 나타나고 자동으로 선택됩니다. 실제 DB에서 층을 결정하는 것은 이름이 아니라 건물 코드와 층 코드입니다. 이름은 알아보기 좋게, 코드는 팀 표기 그대로 넣으세요.

팀 데이터 전체가 틀어지는 세 가지

1

건물 코드는 팀 표기 그대로, 대소문자까지

팀에서 정한 코드를 사용하고 기존 건물에 연결됐는지 소속 목록에서 확인하세요. 대소문자·별칭만으로 새 건물 여부를 추정하지 않습니다.

2

건물 이름은 첫 층을 만든 사람의 값으로 굳습니다

같은 건물 코드로 두 번째 층을 만들 때 다른 건물 이름을 넣어도 바뀌지 않습니다. 이 이름은 검색 결과에 그대로 나옵니다. 건물의 첫 레이어를 만들기 전에 팀에서 이름을 확정하세요.

3

호실 번호는 원문과 팀 표기대로

호실 번호는 301, C301, B208-2 등 원문과 팀 규칙에 맞춰 보존합니다. 이름·호실 번호에서 실제 건물·층을 추측하지 말고 소속 설정과 저장 후 검색 표시명을 확인하세요.

복합 도면·공용 경로

G4/H1처럼 한 도면에 여러 실제 소속을 등록할 수 있습니다. 허용 소속 추가·허용 소속 저장 후 새 노드 기본 소속을 선택합니다. 기존 Point는 선택 노드 소속 변경으로 수정하며 좌표는 유지합니다.

SHARED_PATHS는 높이·통로별로 만듭니다. 공용 노드는 건물·층 소속이 없으며 내부 값 floor: "0"은 실제 0층이나 지상 높이가 아닙니다. 복합·공용·외부 참조 레이어는 복사할 수 없습니다.

이름 변경 · 복사 · 삭제

버튼하는 일하지 않는 일
이름 변경목록에 보이는 이름만 바꿉니다.C동 3층을 C동 4층으로 이름만 바꿔도 층 매핑은 그대로 3층입니다.
복사단일 소속 도면에서 건물·층 정보를 다시 묻고, 현재 층의 노드와 층 안의 간선을 새 ID로 복제해 새 레이어를 만듭니다. 비슷한 층을 만들 때 씁니다.도면 사진과 층간 연결은 복사하지 않습니다. 새 층에 사진을 따로 올리고 연결도 따로 만듭니다. 복사된 이름·호실 번호는 새 층에 맞게 고칩니다.
삭제삭제할 레이어 이름을 정확히 입력하세요.에 이름을 그대로 다시 넣어야 실행됩니다. 외부 연결이 남아 있으면 삭제가 차단됩니다. 연결을 먼저 해제한 뒤 소유 노드·간선·사진을 삭제합니다.되돌릴 수 없고 휴지통도 없습니다. 팀 확인 없이 누르지 않습니다. 건물 자체를 나타내는 항목은 남습니다.

이미 있는 이름이면 이미 사용 중인 레이어 이름입니다, 이미 있는 건물·층이면 해당 건물과 층의 레이어가 이미 존재합니다.가 뜹니다. 후자는 누군가 이미 만든 층이니 새로 만들지 말고 목록에서 고르세요.

04

도면 사진

사진은 지도에 고정됩니다. 지도를 움직이면 따라오고, 조작 키를 누른 동안만 사진 자체를 만집니다.

  1. 작업할 레이어가 선택된 상태인지 먼저 확인합니다. 사진은 선택된 레이어에 올라갑니다.
  2. 지도를 그 건물 위로 옮기고 크게 확대합니다. 지도 기울기(pitch)는 0으로 둡니다.
  3. 도면 파일을 패널의 업로드 영역에 끌어다 놓거나, 영역을 클릭해 고릅니다. 사진이 현재 지도 중심에 놓이고 자동으로 선택됩니다.
  4. 투명도를 절반쯤 낮춰 배경 지도와 도면이 겹쳐 보이게 합니다.
  5. 조작 키를 누른 채 위치·크기·각도를 맞춥니다. 건물 외곽 모서리나 계단실처럼 지도에서도 알아볼 수 있는 곳을 기준으로 삼으세요.

두 가지 모드

패널 헤더의 배지가 지금 어느 모드인지 알려 줍니다. 조작 키는 토글이 아니라 누르고 있는 동안만입니다.

하고 싶은 일조작
지도 이동·확대, 점·선 편집키를 누르지 않고 geojson.io를 그대로 씁니다
사진 이동⌘ + 사진 본체 드래그. 커서 아래의 사진이 자동으로 선택됩니다
크기 조절⌘ + 꼭짓점·모서리 핸들 드래그. 비율은 유지되고 반대편이 고정됩니다
회전⌘ + 상단 회전 핸들 드래그. 스냅 없이 0.1° 단위
확대·축소⌘ + 휠. 커서 위치를 기준으로 커지고 작아집니다
미세 회전⌘ + Shift + 휠. 한 칸에 1°
수치로 맞추기패널 슬라이더와 +·−·±90° 버튼

조작을 마친 사진은 새 위치·크기·각도로 지도에 다시 고정됩니다. 그 뒤로 지도를 아무리 움직여도 같은 자리를 지킵니다. 지도만 움직인 것은 편집으로 치지 않으므로 저장이 일어나지 않습니다.

로컬 도면 캐시와 기준점

처음 받은 도면은 확장 로컬 캐시에서 재사용하며 페이지·Chrome을 다시 열어도 유지됩니다. 직접 업로드한 파일도 다시 받지 않고 캐시합니다. 서버 주소·이미지 주소·내용 해시가 같은 원본만 사용하고 지도 데이터와 배치는 서버에서 확인합니다. 최대 128 MiB·256장을 보관하고 동시 다운로드는 2장입니다.

정렬을 마친 서버 사진을 선택한 뒤 평면도 기준점 1·2에서 사진을 지정하고 두 꼭짓점을 찍어 저장합니다. pitch는 0으로 유지하고 사진을 이동·확대·회전했다면 다시 지정합니다. 기준점은 GeoJSON 내보내기에 포함되지 않아 미저장 좌표를 별도 백업합니다.

리셋과 제거

  • 리셋은 실행 취소가 아닙니다. 선택한 사진의 변형을 모두 초기화하고 현재 지도 중심으로 되돌리는 버튼입니다.
  • 선택 사진 제거와 목록의 ×는 레이어가 선택된 상태에서는 서버에서 사진을 지웁니다. 다른 작업자의 화면에서도 사라집니다.

레이어를 고르지 않고 올린 사진

업로드는 됩니다. 다만 그 사진은 내 Chrome에만 저장되고 서버에도 팀원에게도 가지 않습니다. 이 상태에서 레이어를 선택하면 아래 질문이 뜹니다.

로컬에만 저장된 이미지 N장을 선택한 레이어로 가져올까요?

확인

사진 파일만 선택한 레이어에 업로드합니다. 맞춰 둔 위치·크기·각도는 옮겨지지 않으니 다시 맞춥니다. 지금 고르는 층의 도면일 때만 확인하세요.

취소

가져오기만 취소됩니다. 레이어 전환은 그대로 진행되고 사진 목록은 그 레이어의 사진으로 바뀝니다. 로컬 사진 목록은 따로 남지 않습니다.

로컬 사진을 잃고 싶지 않다면 레이어를 고르기 전에 사진 영역 아래 내보내기로 파일을 받아 두세요. 처음부터 레이어를 먼저 고르고 올리는 편이 안전합니다.

05

점과 선

Point가 노드, LineString의 꼭짓점 사이가 간선이 됩니다. 저장할 수 있는 도형은 이 둘뿐입니다.

기본 편집

  1. geojson.io 상단의 Point 도구로 출입구·갈림길·목적지를 찍습니다.
  2. Line 도구로 실제로 걸어갈 수 있는 경로를 긋습니다. 꼭짓점이 두 개 이상이어야 합니다.
  3. Select 도구로 점이나 꼭짓점을 끌어 위치를 다듬습니다.
  4. 저장이 끝나면 선의 꼭짓점 자리에 Point가 새로 보일 수 있습니다. 서버가 정리해 돌려준 결과이며 정상입니다.
Polygon·Rectangle·Circle 도구는 쓰지 않습니다. 저장이 거절됩니다. Point와 LineString만 저장할 수 있습니다

신규 배치는 복도 중심선 골격과 실제 문 위치의 POI를 구분하고 짧은 접근 간선으로 연결합니다. 확인되지 않은 문·소속·통행 가능 구간은 추측하지 않습니다. 기존 그래프 구조나 도면 정렬은 요청 없이 바꾸지 않습니다.

노드·간선 A–G 표시

Point 또는 LineString을 선택하고 노드·간선 표시에서 색을 누릅니다. A=빨강, B=주황, C=노랑, D=초록, E=파랑, F=남색, G=보라입니다. 여러 대상을 함께 표시하거나 선택 표시 지우기로 지울 수 있습니다. 간선 표시는 선 전체에 적용되고 참조 데이터는 읽기 전용입니다. 저장 상태를 확인하세요.

Point에 정보 넣기

Point를 하나만 선택하면 패널의 선택 Point 영역이 활성화됩니다. 값을 넣은 뒤 선택 Point 반영을 반드시 누르세요. 누르지 않으면 편집기에 반영되지 않습니다.

이 지점은노드 유형검색 가능이름 / 호실 번호
강의실·사무실·화장실처럼 사람이 찾아갈 목적지POI켬이름 필수. 호실은 원문·팀 표기 유지
계단·엘리베이터 앞VERTICAL_LINK끔이름 권장. 06에서 찾아야 합니다

복도가 꺾이기만 하는 곳WAYPOINT끔비워 둠
  • 검색 가능은 사람이 목적지로 검색할 지점에만 켭니다. 복도용 점까지 켜면 검색창이 복도로 뒤덮입니다. 켠 채 이름을 비우면 검색 가능 Point에는 이름이 필요합니다.
  • 유형을 정하지 않은 Point는 WAYPOINT로 저장됩니다.
  • 영역 아래 Node #123은 저장 뒤 서버가 준 번호입니다. 아직 저장 후 Node ID가 부여됩니다라면 그 점은 서버에 없는 것입니다.

선이 이어진다는 것

화면에서 두 선이 교차해 보이는 것과 경로가 이어진 것은 다릅니다. 갈림길에서는 두 선이 같은 꼭짓점을 공유해야 합니다. 서버는 저장할 때 다음 규칙으로 꼭짓점과 Point를 같은 노드로 묶습니다.

  • 아직 노드 번호가 없는 선 꼭짓점은 같은 레이어·같은 실제 건물·층의 1 m 안에 있는 가장 가까운 노드를 재사용할 수 있습니다. 그래서 연결할 Point를 먼저 저장해 두고, 그 위에 꼭짓점을 맞추는 순서가 좋습니다.
  • 이미 노드 번호가 있는 꼭짓점은 근처에 다른 Point가 있어도 자동으로 옮겨 붙지 않습니다.
  • 같은 노드의 좌표는 약 2 cm 오차까지만 같은 것으로 봅니다. 한 번의 저장 안에서 같은 노드를 Point에서 한 번, 선에서 또 한 번 서로 다른 곳으로 옮기면 거절됩니다. Point와 LineString 정점의 이동 위치가 서로 다릅니다 한쪽만 옮기고 저장이 끝난 뒤 다음을 하세요.
  • Point를 옮기면 저장 뒤 그 노드를 쓰는 모든 선의 꼭짓점이 따라옵니다. 선의 꼭짓점을 옮겨도 대응 Point와 다른 선에 반영됩니다.
  • AUTO 가중치는 좌표로 계산합니다. MANUAL은 구간마다 양수를 지정하며 기존 수동 비용은 임의로 바꾸지 않습니다. 실내 여부와 이동 유형은 별개입니다.

지우기

Select로 고른 뒤 geojson.io의 휴지통을 씁니다. 삭제도 다음 자동 저장 때 서버에 반영되므로 상태 줄을 확인해야 진짜로 지워진 것입니다.

Point를 지우려면

① 그 점을 지나는 모든 선에서 꼭짓점을 빼거나 선을 지웁니다. ② 저장 완료를 확인합니다. ③ 그다음 Point를 지웁니다. 순서를 건너뛰면 LineString이 참조하는 Point는 먼저 선에서 분리해야 삭제할 수 있습니다. 다른 레이어와 연결된 점은 연결 소유 레이어에서 해당 선을 먼저 삭제합니다. 레이어 없는 구형 연결은 이전 도구로 가져와 관리합니다.

간선을 지우려면

선 전체를 지우면 그 선의 구간들이 지워지고 Point는 남습니다. A–B–C에서 B 꼭짓점만 빼면 경로가 끊기는 게 아니라 A–C로 이어집니다. 특정 구간만 끊으려면 선을 지우고 남길 구간을 A–B, C–D 두 선으로 다시 긋습니다. 기존 Point 위에 꼭짓점을 맞추면 같은 노드를 씁니다.

JSON을 직접 고칠 때

geojson.io의 JSON 편집기로 고친 내용도 동기화됩니다. 좌표 순서는 [경도, 위도]입니다. 다음 값은 서버가 점·선을 서로 잇는 데 쓰는 것이니 손대지 마세요: id, properties.overlayable과 그 안의 nodeId·editorId·vertexNodeIds·vertexRefs·segmentEdgeIds. 다른 층의 JSON을 붙여넣고 ID만 바꾸는 대신 레이어 복사를 쓰세요.

06

층과 층 잇기

참조 노드를 명시적으로 연결하고 이동 유형·실내 여부·비용을 확인합니다.

실제 이동이 확인된 구간에만 연결합니다. 같은 도면 안의 다른 건물·층도 노드의 실제 소속으로 구분합니다.

  1. 연결 간선을 관리할 레이어를 선택합니다. 다른 레이어의 노드는 읽기 전용 참조로 추가합니다.
  2. 현재 레이어에 LineString을 만들고 선택합니다.
  3. 노드 목록에서 건물·층·이름 또는 ID로 끝점을 찾아 선의 시작점·끝점에 연결합니다. 원본 Point를 복제하지 않습니다.
  4. 이동 유형, 실내 여부, 양방향 여부를 확인하고 수동 비용은 구간 수에 맞춰 지정합니다.
  5. 저장 후 원본 노드 ID·연결·비용을 다시 확인합니다.
참조 끝점은 원본 위치에 고정됩니다. 이동은 원본 레이어에서 합니다. 참조 표시를 숨겨도 연결은 남습니다. 기존 층 연결 버튼은 호환 기능이며 새 연결은 위 v2 절차를 사용하세요.

공용 경로는 높이·통로별로 분리합니다. 야외 계단은 STAIR + indoor=false, 실내 공용 통로는 CORRIDOR + indoor=true로 지정합니다. 기존 데이터 이전은 후보 확인 → 미리보기 → 별도 실행 → 재조회 순서로 진행합니다.

07

저장과 공동 작업

저장 버튼 대신 상태 줄을 봅니다. 열려 있는 동안 약 10초마다 서버와 맞춥니다.

매 주기마다 확장은 편집기의 점·선과 사진 배치를 서버에 마지막으로 보낸 것과 비교합니다. 달라졌으면 저장하고, 서버가 정리해 돌려준 결과를 편집기에 다시 반영합니다. 달라진 게 없으면 서버 쪽에 새 버전이 있는지만 확인합니다. revision은 그 레이어의 변경 횟수입니다.

상태 줄뜻과 다음 행동
저장 중…보내는 중입니다. 기다립니다.
저장됨 · revision N내 변경이 서버에 들어갔습니다. 이걸 보고 나서 층을 바꾸거나 탭을 닫습니다.

원격 변경 반영 · revision N다른 탭이나 작업자의 변경을 가져와 편집기에 반영했습니다.
동기화 실패: …저장 성공으로 간주하지 말고 뒤에 붙은 문구를 오류 문구 찾기에서 찾습니다. 조회 실패는 간격을 늘려 재시도합니다. 저장 결과가 불확실하거나 충돌하면 자동 저장을 멈춥니다.
충돌: 다른 작업자가 변경했습니다. …내가 마지막으로 본 뒤 서버가 바뀌었습니다. 내 편집은 화면에 남고 자동 저장이 멈춥니다. 아래 절차대로 합니다.
저장됨 또는 동기화됨을 보기 전에는 레이어를 바꾸지도, 탭을 닫지도, 새로고침하지도 마세요. 10초는 타이머 간격일 뿐이고, 네트워크나 백그라운드 탭 제한 때문에 더 늦어질 수 있습니다.

변경이 없으면 현재·연결 레이어의 버전만 확인하고, 바뀌었을 때 전체 데이터를 가져옵니다. 이전 백엔드는 기존 전체 조회로 동작합니다. 숨겨진 탭에서는 원격 조회를 쉬지만 미저장 변경은 계속 저장합니다. 조회 실패 시 간격은 10 → 20 → 40 → 80초 → 최대 2분으로 늘어납니다.

저장 결과 확인이 필요해 자동 저장을 멈췄습니다…가 나오면 서버가 이미 처리했을 수 있습니다. 자동 재전송과 층 전환을 중단하므로 아래처럼 백업한 뒤 원격 다시 불러오기로 확인합니다. 요청 대기 제한은 20초입니다. 충돌 후에도 다시 불러올 때까지 자동 저장을 중단합니다.

층 전환 중 여러 층을 선택하면 마지막 선택을 반영합니다. 새 도면 준비가 실패하면 기존 층을 유지합니다.

충돌이 났을 때

  1. 편집을 멈춥니다.
  2. GeoJSON 내보내기로 내 점·선을 파일로 받습니다.
  3. 사진 배치도 지켜야 한다면 하단 내보내기도 누르고, 미저장 기준점 좌표는 별도로 복사합니다.
  4. 다른 작업자와 어느 쪽 변경을 남길지 정합니다.
  5. 원격 다시 불러오기를 누르고 저장되지 않은 GeoJSON·사진 배치·기준점 변경을 버리고 원격 데이터를 불러올까요?에 확인합니다.
  6. 서버 상태 위에 필요한 변경만 다시 적용하고 저장됨을 확인합니다.
원격 다시 불러오기는 복구 버튼이 아닙니다. 내 미저장 점·선·사진 배치·기준점을 버리고 서버 상태로 바꿉니다. 반대로 내가 받아 둔 JSON 전체를 그대로 다시 붙여넣으면 다른 사람의 변경을 덮어씁니다. 자동으로 합쳐 주는 기능은 없습니다.

팀 원칙

  • 모두 같은 서버 주소와 같은 키를 씁니다.
  • 한 층은 한 사람이 편집합니다. 같은 층을 두 탭에서 열어 두고 양쪽에서 고치면 충돌합니다.
  • 다른 사람이 새로 만든 레이어나 바꾼 이름이 목록에 안 보이면, 내 변경을 저장·백업한 뒤 페이지를 새로고침합니다. 10초 동기화는 현재 레이어의 내용만 맞추고 레이어 목록은 갱신하지 않습니다.
  • 레이어·사진 삭제는 공유 데이터에 영향을 줍니다. 원격 다시 불러오기는 내 미저장 편집을 버리므로 먼저 백업합니다.

연결은 됐는데 남의 레이어가 안 보인다서로 다른 서버를 보고 있습니다. 내가 localhost에 붙어 있지 않은지, 주소·포트가 팀 주소와 같은지 확인합니다.
Chrome을 다시 켰더니 연결이 끊겼다정상입니다. 키는 세션에만 남습니다. 키를 다시 넣고 연결. 주소와 마지막 레이어는 기억돼 있습니다.
지도 감지 대기 중이 사라지지 않는다미저장 내용을 내보낸 뒤 chrome://extensions에서 확장 ↻ → geojson.io 새로고침. 개발자 도구(F12) 콘솔에 [Overlayable] 지도 연동 성공이 찍히면 정상, 지도를 찾지 못했습니다가 찍히면 사이트 구조 변화이니 개발자에게 알립니다.
선택 Point 반영이 눌리지 않는다선이나 여러 개가 선택돼 있습니다. Point 하나만 고릅니다.
저장 뒤 선 꼭짓점 자리에 Point가 생겼다정상입니다. 서버가 꼭짓점을 노드로 정리해 돌려준 것입니다.
지운 Point가 다시 나타난다그 점을 쓰는 선이나 층간 연결이 남아 있어 삭제가 거절된 것입니다. 상태 줄의 동기화 실패를 확인하고 05의 지우기 순서를 따릅니다.
경로가 이어진 것 같은데 안 이어진다두 선이 같은 꼭짓점을 공유하는지 봅니다. 겹쳐 보이는 것과 공유는 다릅니다. 갈림길의 Point를 먼저 저장하고 두 선의 꼭짓점을 모두 그 위에 맞춥니다.
다른 층에서 사진이 안 보인다사진은 소유 레이어에서 편집합니다. 다른 도면은 참조로 볼 수 있고, 복사한 층의 새 도면은 따로 올립니다.
사진이 지도와 어긋난다지도 연동됨인지, 지도 기울기가 0인지 확인하고 다시 맞춥니다.
가져온 사진이 팀원에게 안 보인다사진 영역의 가져오기는 내 Chrome에만 합칩니다. 레이어를 고른 뒤 업로드 영역으로 올려야 공유됩니다.
사진이 갑자기 사라졌다극단적으로 확대하면 잠시 숨깁니다. 줌을 되돌리면 나타납니다. 레이어를 바꿨다면 그 층의 사진이 아닌 것입니다.

하지 말 것

한 번 하면 되돌리기 어렵거나, 남의 데이터를 건드리는 일.

Polygon·Rectangle·Circle로 그리기저장되지 않습니다. Point와 LineString만 씁니다.
JSON에서 id·nodeId·editorId·vertexNodeIds·vertexRefs·segmentEdgeIds 고치기점과 선이 서로 어긋나 저장이 거절되거나 남의 데이터를 덮습니다.
다른 층 JSON을 복사해 ID만 바꿔 붙여넣기단일 소속 도면의 비슷한 층은 복사 버튼을 씁니다. 노드·간선이 새 ID로 복제됩니다.
팀 확인 없이 레이어 삭제외부 연결을 먼저 해제해야 하며, 삭제한 소유 점·선·사진은 되돌릴 수 없습니다.
팀 확인 없이 원격 다시 불러오기내 미저장 편집이 사라집니다. 먼저 내보냅니다.
같은 층을 두 사람이 동시에 편집자동 병합이 아닙니다. 양쪽에 변경이 있으면 충돌합니다.
내 localhost에 붙어서 작업나만의 DB에 쌓입니다. 팀 공용 주소를 씁니다.
외부 서버를 http://로 쓰기키와 데이터가 암호화되지 않습니다. HTTPS를 씁니다.
관리자 키를 채팅·스크린샷·문서에 남기기서버의 모든 레이어를 지울 수 있는 키입니다.
저장됨을 보기 전에 탭 닫기·새로고침·레이어 전환마지막 편집이 서버에 가지 않았을 수 있습니다.
